## 5. 현재 검증 범위

파일 선별/참조 누락/문법/기존 회귀 테스트의 실제 결과는 [validation.json](validation.json)에, 운영 파일 해시와 별도 로컬 DB 기동 후 검증은 [deployment-verification.json](deployment-verification.json)에 기록합니다. 두 검증의 범위를 구분합니다.

재검사 명령은 `python tools/validate_final_pr.py --node <Node.js 실행파일> --docker <Docker 실행파일>`입니다. 먼저 [로컬 시작 안내](../../app/gb-system/README.md)로 이미지를 생성합니다. Python AST·JavaScript 문법·Docker COPY·HTML/동적 팬 이미지 참조·최적화 이미지 24개·폰트 참조 64개·번들/원본 해시 39개·명시적으로 선택한 Python 회귀 테스트·JS 테스트를 검사합니다. 실제 DB가 필요한 비교 테스트 1개는 이 검사에서 제외(skip)하며 별도 로컬 API 조회로 보완했습니다. 비밀 값 검색은 알려진 형식에 대한 검사입니다.

- 배포 대조: v18 앱 파일 205개 중 미사용 파일 33개는 제외하고, 남긴 172개 중 실행 코드/자산 171개는 원본과 일치합니다. 최적화 이미지 목록 1개는 미사용 항목만 제거합니다. CSV 사본 5개는 이 배포 목록 205개에 원래 포함되지 않았습니다. 변경된 공개 코드의 운영/체험 경로 18개는 해시 일치, 운영 health 정상입니다.
- 직접 확인: 별도 로컬 Docker 빌드·기동, 팀장 6대/소결 3대/제강 3대 조회, 보고서 승인 메타데이터와 공정 범위, 체험/관리 세션 분리.
- 경량본 최종 확인: 기존 회귀 테스트 92개 통과·DB 비교 1개 제외, 이미지/폰트 HTTP HEAD 115개·WebP 전환 24개 정상, Git 줄바꿈 보호 경로 249개 확인. 제외된 옛 자산이 로컬 서버에서 제공되지 않는 것도 확인했습니다.
- 배포 대화의 증빙 인용: DB 테이블 30개, 이번 배포의 DB 변경 0건, 환경값·푸시 키 유지, 시험 알림 0건. 이 채팅에서 운영 DB 전체를 다시 대조했다는 뜻은 아닙니다.
- 실제 운영 보고서·승인 화면은 배포 대화에서 검증했습니다. 이번 PR 검사에서는 전체 실제 기기 UI·메일/푸시 실발송·운영 쓰기 흐름을 다시 실행하지 않았습니다.
- 이전 성능 개선 수치를 v18의 새 측정치로 표시하지 않습니다. 이번 검사는 회귀와 배포 일치 확인이며 새 성능 벤치마크는 아닙니다.
